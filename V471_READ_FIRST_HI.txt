V471 • V470 पर संयुक्त बदलाव
1. Supabase की परीक्षण कॉपी में 01_MARKS_SYNC_V471.sql चलाएँ। यह V464 की teacher bell function और मौजूदा V320 Exam engine का उपयोग करती है। पहले त्रुटि पर रुकें। पुराने Assign Work SQL दोबारा चलाना इस बदलाव का हिस्सा नहीं है।
2. मौजूदा ERP की परीक्षण शाखा में ZIP से index.html, dashboard-v332.js, dashboard-order-v350.js, work-access-v398.js, exam-central-v320.js और erp-premium-cards.css मूल root में बदलें।
3. Admin Dashboard → Fee Pay → विद्यार्थी खोजें → जोड़ें → राशि → सेव। सर्वर की पुष्टि के बाद अगला विद्यार्थी खोजें बटन सामने आता है। इसे दबाने पर खोज खाली होकर फोकस होती है। रसीद देखना / प्रिंट भी उपलब्ध है।
4. Teacher Dashboard → मौजूदा Exams & Marks कार्ड → अधिकृत पेपर → Load / Resume → अंक → Save Changed Marks। केवल उपस्थिति Present वाली row में अंक दर्ज होंगे। पुरानी कॉपी चेक प्रगति अलग है। एक ही transaction में scope, revisions, attendance, केंद्रीय अंक और student_marks अपडेट होते हैं। यदि परिणाम समन्वय असफल हो तो पूरा सेव rollback होता है। पहले से जारी मार्कशीट को दोबारा जारी या अधिलेखित नहीं किया जाता। खुले दूसरे उपकरण पर नया डेटा अगली बार पढ़ने पर दिखेगा।
5. Admin → Assign Work खोलने पर मूल कार्य सूची और फ़ॉर्म पहले खुलते हैं। वहीं Management कार्ड / नए काम सौंपें से उसी कार्य केंद्र में बाद के कार्ड खुलते हैं। अधिकार और पुराने कामों के टैब भी उपलब्ध हैं।
जाँच: उपलब्ध Supabase CSV में स्थापित list/load/save की परिभाषा पढ़कर मापदंड मिलाए। 128 inline scripts और बदली JS का syntax, Teacher route (mock paper), Parent guard, शुल्क रसीद और अगली खोज का व्यवहार mock DOM में जाँचा। नया SQL वास्तविक सर्वर पर चलाया नहीं है। वास्तविक Admin/Teacher login, अभिभावक परिणाम, mobile/laptop layout एवं RLS acceptance अभी बाकी हैं। staging में दो अलग शिक्षक/सेक्शन, blank/zero, duplicate retry और एक receipt की जाँच कर मुख्य ERP में लगाएँ।
