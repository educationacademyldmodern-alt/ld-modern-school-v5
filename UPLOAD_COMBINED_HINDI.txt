V404 + V405 — एक संयुक्त UPDATE ZIP

आपने V404 / V405 अभी upload नहीं किए हैं तो दोनों की जगह केवल यही ZIP इस्तेमाल करें। यह V403 Rechecked installed ERP के ऊपर लगाने के लिए है; fresh installation नहीं।

1. ZIP extract करें। Root की सभी 12 HTML / JS / CSS / JSON files को ERP / GitHub के उसी root पर upload / replace करें। एक ही नाम की file की एक final copy दी गई है। V404 के सुधार और V405 की नई दैनिक जाँचें दोनों शामिल हैं।
2. ERP की बाकी files / folders न हटाएँ। मौजूदा V403 dependencies और udise-v306-devanagari.woff2 font रहने दें। पुराने दोनों ZIP अलग से upload न करें।
3. Supabase SQL Editor में इस क्रम से नए पाँच SQL चलाएँ:
   पहला: SQL_V404/01_STAFF_RECIPIENTS_SAFE.sql
   दूसरा: SQL_V405/01_ACCESS_AND_HISTORY.sql
   तीसरा: SQL_V405/02_READ_SOURCES.sql
   चौथा: SQL_V405/03_ACTIONS.sql
   पाँचवाँ: SQL_V405/04_REPORT_DETAILS.sql
   हर SQL part 25 KB से छोटा है। पुराने सफल V398 / V403 migrations दोबारा न चलाएँ। यदि ऊपर के किसी SQL को पहले सफलतापूर्वक चला चुके हैं तो उसे अनावश्यक दोहराने की जरूरत नहीं।
4. HTML / JS / JSON / font files SQL Editor में नहीं डालें। VERIFY_V405, निर्देश और checksums GitHub पर upload करना जरूरी नहीं है।
5. सही branch के deployment Ready होने के बाद refresh करें। GitHub upload commit को live ERP verification न मानें।

Authority
School Management: सभी नई दैनिक जाँचें / Reminders / Reports / Leave निर्णय। वास्तविक Fee transaction और Exam Attendance / Marks के लिए Fee Authority / Exam Authority भी अलग select करें। Login का मूल role Admin नहीं बनता। Expiry / Revoke server पर जाँचे जाते हैं।

SQL और data व्यवहार
स्थापना नई queue / history tables, indexes और functions बनाती है, module catalog में विकल्प जोड़ती है। पुराने ERP records delete नहीं किए जाते और login roles / मूल RLS policies नहीं बदलते। Installation से reminders नहीं भेजे जाते या fee / attendance / leave अपने-आप नहीं बदलते।
इस्तेमाल पर reminder queue और review history सेव होते हैं। Leave निर्णय मूल central service चला सकता है; उसके business rules से leave / attendance बदल सकती है। मूल सेवाओं के अंदर उपलब्ध update / delete व्यवहार को इस update से हटाया नहीं गया है। Staff Leave register decision status बदलता है; attendance sync का दावा नहीं। Fee reversal / payment जैसे actions मूल वित्तीय records बदल सकते हैं और केवल user action पर चलते हैं।

जाँच
यह दोनों पहले जाँचे packages की files का संयुक्त package है। साझा files की V405 copy रखी गई है; V404 की बाकी आवश्यक files / reader dependency छोड़ी नहीं गई है। ZIP CRC, unique paths, original tested bytes और checksum जाँचे गए हैं।
स्थानीय SQL / browser जाँच Admin और Teacher के 390px / 1366px sizes पर हुई थी; 2000 विद्यार्थियों / 120000 attendance records का स्थानीय test भी पास था। VERIFY_V405 में मूल evidence है; उसकी V404 prerequisite इस संयुक्त ZIP में शामिल है।
Live ERP / production SQL / physical printer / final PDF pagination / actual message delivery अभी सत्यापित नहीं हैं। 0-second / कभी hang न होने या हर पुराने विशेष Admin tool का पूर्ण delegation होने का दावा नहीं है। Source report export की सीमा 5000 rows है; बड़ी report के लिए मूल module filter का संदेश आएगा, अधूरा export नहीं।
